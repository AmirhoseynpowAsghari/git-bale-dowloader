# ربات ارسال تغییرات GitHub به گروه بله

ربات روزانه تغییرات یک ریپازیتوری GitHub را بررسی می‌کند و فقط نسخه جدید فایل‌های افزوده یا ویرایش‌شده را با API بله به یک گروه می‌فرستد. فایل‌های حذف‌شده و تغییرنام‌یافته هم گزارش می‌شوند. نیازی به سرور نیست؛ GitHub Actions اجرا می‌کند.

## ۱) ساخت ربات بله

1. در بله، [@botfather](https://ble.ir/botfather) را باز کنید و ربات بسازید.
2. **توکن ربات را محرمانه نگه دارید**.
3. ربات را به گروه خود اضافه کنید و اجازه ارسال پیام و فایل به آن بدهید (در صورت لزوم مدیر کنید).
4. یک پیام در گروه بفرستید (مثلاً `/start` با اشاره به ربات).
5. برای دریافت شناسه گروه، URL زیر را **فقط برای خودتان** در مرورگر باز کنید؛ به جای `YOUR_TOKEN` توکن را قرار دهید:
   `https://tapi.bale.ai/botYOUR_TOKEN/getUpdates`
6. مقدار `result[].message.chat.id` مربوط به گفت‌وگویی که `chat.type` آن `group` است را بردارید. اگر خالی بود، پیام دیگری به ربات در گروه بفرستید و دوباره امتحان کنید. اگر قبلاً webhook تنظیم شده، باید آن را غیرفعال کنید تا `getUpdates` کار کند.

> URL حاوی توکن را برای کسی نفرستید و در ریپازیتوری ذخیره نکنید. پس از کار بهتر است سابقه مرورگر را پاک کنید.

## ۲) آماده‌سازی GitHub

1. یک ریپازیتوری که مالک آن هستید انتخاب کنید (می‌تواند خود ریپازیتوری مورد نظارت باشد یا ریپازیتوری اختصاصی ربات).
2. پوشه‌ها و فایل‌های این بسته را با همین ساختار در **شاخه پیش‌فرض** ریپازیتوری قرار دهید.
3. وارد **Settings → Secrets and variables → Actions → New repository secret** شوید و دو Secret بسازید:
   - `BALE_BOT_TOKEN`: توکن ربات بله
   - `BALE_CHAT_ID`: شناسه عددی گروه
4. فایل `.github/workflows/bale-watcher.yml` را باز کنید. برای بررسی همان ریپازیتوری، `MONITOR_REPO: ${{ github.repository }}` را تغییر ندهید. برای یک ریپازیتوری عمومی دیگر، به جای آن `MONITOR_REPO: "owner/repo"` قرار دهید.
5. `MONITOR_BRANCH: ""` یعنی شاخه اصلی ریپازیتوری هدف؛ می‌توانید مثلاً `"main"` تعیین کنید.
6. از تب **Actions → Send GitHub changes to Bale → Run workflow** اجرای آزمایشی را شروع کنید.

**نتیجه اجرای اول:** یک پیام «پایش فعال شد» در گروه و ایجاد شاخه `bale-watcher-state`، بدون ارسال همه فایل‌های قبلی.

**آزمایش تغییر:** یک فایل در شاخه مورد نظارت تغییر دهید، commit و push کنید و دوباره **Run workflow** را بزنید؛ فایل تغییرکرده باید به گروه برسد.

## ۳) زمان‌بندی

تنظیم فعلی `23 4 * * *` هر روز حدود ساعت **۷:۵۳ صبح ایران** است (04:23 UTC). GitHub ممکن است اجرای زمان‌بندی‌شده را با تأخیر انجام دهد یا نادراً از دست بدهد؛ ربات در اجرای موفق بعدی فاصله میان دو commit ثبت‌شده را بررسی می‌کند.

GitHub در ریپازیتوری‌های عمومی بی‌فعالیت ممکن است زمان‌بندی Actions را پس از ۶۰ روز غیرفعال کند؛ در صورت نیاز آن را دوباره فعال کنید.

## نحوه نگهداری وضعیت

شناسه آخرین commit بررسی‌شده در `bale-watcher-state.json` روی شاخه جداگانه `bale-watcher-state` ذخیره می‌شود، نه شاخه اصلی. این شاخه را حذف نکنید. برای راه‌اندازی دوباره از صفر، شاخه را حذف کنید؛ در اجرای بعدی نقطه شروع جدید ثبت می‌شود.

## محدودیت‌ها و نکات

- برای ارسال فایل سقف محافظه‌کارانه **۴۵ MiB** در کد اعمال شده تا از سقف اعلام‌شده ۵۰ مگابایت بله عبور نکند؛ فایل بزرگ‌تر ارسال نمی‌شود و در گزارش می‌آید.
- API مقایسه GitHub حداکثر ۳۰۰ فایل تغییریافته را گزارش می‌کند؛ اگر تعداد تغییرات به ۳۰۰ برسد، ربات به‌جای رد شدن خاموش از فایل‌ها، با خطا متوقف می‌شود و وضعیت را جلو نمی‌برد.
- در صورت قطع ارتباط بعد از ارسال بعضی فایل‌ها و پیش از ذخیره وضعیت، اجرای بعدی ممکن است همان فایل‌ها را تکرار کند. ارسال کاملاً exactly-once بدون رسید/ذخیره وضعیت تراکنشی قابل تضمین نیست.
- در صورت تغییر تاریخچه Git با force-push، مقایسه ممکن است غیرمنتظره باشد یا خطا بدهد.
- توکن داخلی `GITHUB_TOKEN` فقط به محتوایی که مجاز است دسترسی دارد. یک ریپازیتوری عمومی خارجی قابل بررسی است؛ برای ریپازیتوری خصوصی خارجی به اعتبارنامه دارای دسترسی مجزا و تغییر در کد نیاز است.
- فایل‌های Git LFS و submodule ممکن است به صورت اشاره‌گر/ارجاع Git نمایش داده شوند، نه محتوای واقعی؛ این نسخه آن‌ها را به طور خاص بازیابی نمی‌کند.
- اگر اجرای اول پیام بله را فرستاد ولی ذخیره وضعیت در GitHub خطا داد، مطمئن شوید `contents: write` مجاز است و محدودیت‌های سازمانی یا قوانین محافظت شاخه اجازه ساخت شاخه جدید را می‌دهند.
- حتماً از تب Actions نتیجه اجرا و Log را ببینید؛ این پروژه در محیط واقعی با توکن شما اجرا نشده است.
